Public class function Malloc(n: NativeUInt): Pointer;

Allocates n bytes and returns a pointer to the allocated memory, or nil if the request fails.

Requesting zero bytes returns a distinct non-nil pointer if possible, as if TPyMem.Malloc(1) had been called instead. The memory will not have been initialized in any way.

Public class function Calloc(nelem, elsize: NativeUInt): Pointer;

Allocates nelem elements each of size elsize bytes and returns a pointer to the allocated memory, or nil if the request fails. The memory is initialized to zeros.

Requesting zero elements or elements of size zero bytes returns a distinct non-nil pointer if possible, as if TPyMem.Calloc(1, 1) had been called instead.

Public class function Realloc(p: Pointer; n: NativeUInt): Pointer;

Resizes the memory block pointed to by p to n bytes. The contents will be unchanged to the minimum of the old and the new sizes.

If p is nil, the call is equivalent to TPyMem.Malloc(n); else if n is equal to zero, the memory block is resized but is not freed, and the returned pointer is non-nil.

Unless p is nil, it must have been returned by a previous call to TPyMem.Malloc(), TPyMem.Realloc() or TPyMem.Calloc().

If the request fails, TPyMem.Realloc() returns nil and p remains a valid pointer to the previous memory area.

Public class procedure Free(p: Pointer);

Frees the memory block pointed to by p, which must have been returned by a previous call to TPyMem.Malloc(), TPyMem.Realloc() or TPyMem.Calloc(). Otherwise, or if TPyMem.Free(p) has been called before, undefined behavior occurs.

If p is nil, no operation is performed.

Public class procedure GetAllocator(domain: PyMemAllocatorDomain; out allocator: PyMemAllocatorEx);

Get the memory block allocator of the specified domain.

Public class procedure SetAllocator(domain: PyMemAllocatorDomain; var allocator: PyMemAllocatorEx);

Set the memory block allocator of the specified domain.

The new allocator must return a distinct non-nil pointer when requesting zero bytes.

For the PYMEM_DOMAIN_RAW domain, the allocator must be thread-safe: a thread state is not attached when the allocator is called.

For the remaining domains, the allocator must also be thread-safe: the allocator may be called in different interpreters that do not share a GIL.

If the new allocator is not a hook (does not call the previous allocator), the TPyMem.SetupDebugHooks() function must be called to reinstall the debug hooks on top on the new allocator.

See also PyPreConfig.allocator and Preinitialize Python with PyPreConfig.

Warning TPyMem.SetAllocator() does have the following contract: 

- It can be called after TPy.PreInitialize() and before
  TPy.InitializeFromConfig() to install a custom memory allocator.
  There are no restrictions over the installed allocator other than
  the ones imposed by the domain (for instance, the Raw Domain allows
  the allocator to be called without an attached thread state). See
  the section on allocator domains for more information.
- If called after Python has finish initializing (after
  TPy.InitializeFromConfig() has been called) the allocator must wrap
  the existing allocator. Substituting the current allocator for some
  other arbitrary one is not supported.

Changed in version 3.12: All allocators must be thread-safe.
