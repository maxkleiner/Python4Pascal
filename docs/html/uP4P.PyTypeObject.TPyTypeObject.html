Public class function GetModule(type_: PPyTypeObject): IPyObject;

Return the module object associated with the given type when the type was created using TPyTypeObject.FromModuleAndSpec().

The returned reference is borrowed from type, and will be valid as long as you hold a reference to type. Do not release it with TPy.DECREF() or similar.

If no module is associated with the given type, sets TypeError and returns nil.

This function is usually used to get the module in which a method is defined. Note that in such a method, TPyTypeObject.GetModule(TPy.TYPE(self)) may not return the intended result. TPy.TYPE(self) may be a subclass of the intended class, and subclasses are not necessarily defined in the same module as their superclass. See PyCMethod to get the class that defines the method. See TPyTypeObject.GetModuleByToken() for cases when PyCMethod cannot be used.

Public class function GetModuleState(type_: PPyTypeObject): Pointer;

Return the state of the module object associated with the given type. This is a shortcut for calling TPyModule.GetState() on the result of TPyType.GetModule().

If no module is associated with the given type, sets TypeError and returns nil.

If the type has an associated module but its state is nil, returns nil without setting an exception.

Public class function FromMetaclass(metaclass: PPyTypeObject; const module: IPyObject; spec: PPyType_Spec; const bases: IPyObject): IPyObject;

Create and return a heap type from the spec (see Py_TPFLAGS_HEAPTYPE).

The metaclass metaclass is used to construct the resulting type object. When metaclass is nil, the metaclass is derived from bases (or Py_tp_base[s] slots if bases is nil, see below).

Metaclasses that override tp_new are not supported, except if tp_new is nil.

The bases argument can be used to specify base classes; it can either be only one class or a tuple of classes. If bases is nil, the Py_tp_bases slot is used instead. If that also is nil, the Py_tp_base slot is used instead. If that also is nil, the new type derives from object.

The module argument can be used to record the module in which the new class is defined. It must be a module object or nil. If not nil, the module is associated with the new type and can later be retrieved with TPyTypeObject.GetModule(). The associated module is not inherited by subclasses; it must be specified for each class individually.

This function calls TPyTypeObject.Ready() on the new type.

Note that this function does not fully match the behavior of calling type() or using the class statement. With user-provided base types or metaclasses, prefer calling type (or the metaclass) over TPyTypeObject.From* functions. Specifically:

__new__() is not called on the new class (and it must be set to type.__new__).

__init__() is not called on the new class.

__init_subclass__() is not called on any bases.

__set_name__() is not called on new descriptors.

Added in version 3.12.

Soft deprecated since version 3.15: Prefer TPyType.FromSlots() in new code.

Public class function GetTypeDataSize(cls: PPyTypeObject): Py_ssize_t;

Return the size of the instance memory space reserved for cls, i.e. the size of the memory TPyObject.GetTypeData() returns.

This may be larger than requested using -PyType_Spec.basicsize; it is safe to use this larger size (e.g. with memset()).

The type cls must have been created using negative PyType_Spec.basicsize. Python does not check this.

On error, set an exception and return a negative value.

Added in version 3.12.

Public class function GetBaseByToken(type_: PPyTypeObject; tp_token: Pointer; var result_: PPyTypeObject): integer;

Find the first superclass in type's method resolution order whose Py_tp_token tp_token is equal to the given one. 

- If found, set result_ to a new strong reference to it and return 1.
- If not found, set result_ to nil and return 0.
- On error, set result_ to nil and return -1 with an exception set.

The result_ argument may be nil, in which case result_ is not set. Use this if you need only the return value.

The tp_token argument may not be nil.

Added in version 3.14.

Public class function Ready(type_: PPyTypeObject): boolean;

Finalize a type object. This should be called on all type objects to finish their initialization. This function is responsible for adding inherited slots from a type's base class. Return True on success, or return False and sets an exception on error.

Note: If some of the base classes implements the GC protocol and the provided type does not include the Py_TPFLAGS_HAVE_GC in its flags, then the GC protocol will be automatically implemented from its parents. On the contrary, if the type being created does include Py_TPFLAGS_HAVE_GC in its flags then it must implement the GC protocol itself by at least implementing the tp_traverse handle.

Public class function GenericAlloc(type_: PPyTypeObject; nitems: Py_ssize_t): IPyObject;

Generic handler for the tp_alloc slot of a type object. Uses Python's default memory allocation mechanism to allocate memory for a new instance, zeros the memory, then initializes the memory as if by calling TPyObject.Init() or TPyObject.InitVar().

Do not call this directly to allocate memory for an object; call the type's tp_alloc slot instead.

For types that support garbage collection (i.e., the Py_TPFLAGS_HAVE_GC flag is set), this function behaves like TPyObject.GC_New or TPyObject.GC_NewVar (except the memory is guaranteed to be zeroed before initialization), and should be paired with TPyObject.GC_Del() in tp_free. Otherwise, it behaves like TPyObject.New or TPyObject.NewVar (except the memory is guaranteed to be zeroed before initialization) and should be paired with TPyObject.Free() in tp_free.

Public class function GenericNew(type_: PPyTypeObject; const args, kwds: IPyObject): IPyObject;

Public class function GetModuleByDef(type_: PPyTypeObject; def: PPyModuleDef): IPyObject;

Find the first superclass whose module was created from the given PyModuleDef def, or whose module token is equal to def, and return that module.

Note that modules created from a PyModuleDef always have their token set to the PyModuleDef's address. In other words, this function is equivalent to TPyType.GetModuleByToken(), except that it: 

- returns a borrowed reference, and
- has a non-void* argument type (which is a cosmetic difference in C).

The returned reference is borrowed from type, and will be valid as long as you hold a reference to type. Do not release it with TPy.DECREF() or similar.

Added in version 3.11.

Public class function Freeze(type_: PPyTypeObject): boolean;

Make a type immutable: set the Py_TPFLAGS_IMMUTABLETYPE flag.

All base classes of type must be immutable.

On success, return True. On error, set an exception and return False.

The type must not be used before it's made immutable. For example, type instances must not be created before the type is made immutable.

Added in version 3.14.

Public class function GetDict(type_: PPyTypeObject): IPyObject;

Return the type object's internal namespace, which is otherwise only exposed via a read-only proxy (cls.__dict__). This is a replacement for accessing tp_dict directly. The returned dictionary must be treated as read-only.

This function is meant for specific embedding and language-binding cases, where direct access to the dict is necessary and indirect access (e.g. via the proxy or TPyObject.GetAttr()) isn't adequate.

Extension modules should continue to use tp_dict, directly or indirectly, when setting up their own types.

Added in version 3.12.

Public class function AddWatcher(callback: PyType_WatchCallback): integer;

Register callback as a type watcher. Return a non-negative integer ID which must be passed to future calls to TPyTypeObject.Watch(). In case of error (e.g. no more watcher IDs available), return -1 and set an exception.

In free-threaded builds, TPyTypeObject.AddWatcher() is not thread-safe, so it must be called at start up (before spawning the first thread).

Added in version 3.12.

Public class function ClearWatcher(watcher_id: integer): boolean;

Clear watcher identified by watcher_id (previously returned from TPyTypeObject.AddWatcher()). Return True on success, False on error (e.g. if watcher_id was never registered.)

An extension should never call TPyTypeObject.ClearWatcher with a watcher_id that was not returned to it by a previous call to TPyTypeObject.AddWatcher().

Added in version 3.12.

Public class function Watch(watcher_id: integer; const type_: IPyObject): boolean;

Mark type as watched. The callback granted watcher_id by TPyTypeObject.AddWatcher() will be called whenever TPyTypeObject.Modified() reports a change to type. (The callback may be called only once for a series of consecutive modifications to type, if _PyType_Lookup() is not called on type between the modifications; this is an implementation detail and subject to change.)

The callback is also invoked when a watched heap type is deallocated.

An extension should never call TPyTypeObject.Watch with a watcher_id that was not returned to it by a previous call to TPyTypeObject.AddWatcher().

Added in version 3.12.

Changed in version 3.15: The callback is now also invoked when a watched heap type is deallocated.

Public class function Unwatch(watcher_id: integer; const type_: IPyObject): boolean;

Mark type as not watched. This undoes a previous call to TPyTypeObject.Watch(). type must not be nil.

An extension should never call this function with a watcher_id that was not returned to it by a previous call to TPyTypeObject.AddWatcher().

On success, this function returns True. On failure, this function returns False with an exception set.

Added in version 3.12.

Public class function FromSlots(slots: PPySlot): IPyObject;

Create and return a heap type from a PySlot array. See Definition slots for general information on slots, and Type slot IDs for slots specific to type creation.

This function calls TPyType.Ready() on the new type.

Note that this function does not fully match the behavior of calling type() or using the class statement. With user-provided base types or metaclasses, prefer calling type (or the metaclass) over TPyType.From* functions. Specifically: 

- __new__() is not called on the new class (and it must be set to
  type.__new__).
- __init__() is not called on the new class.
- __init_subclass__() is not called on any bases.
- __set_name__() is not called on new descriptors.

Slots are typically defined as a global static constant arrays. However, sometimes slot values are not statically known at compile time. For example, slots like Py_tp_bases, Py_tp_metaclass and Py_tp_module require live Python objects. In this case, it is recommended to put such slots on the stack, and use Py_slot_subslots to refer to an array of static slots. For example: 

static const PySlot my_slots[] = {
   PySlot_STATIC_DATA(Py_tp_name, "MyClass"),
   PySlot_FUNC(Py_tp_repr, my_repr_func),
   ...
   PySlot_END
};

PyObject *make_my_class(PyObject *module) {
   PySlot all_slots[] = {
      PySlot_STATIC_DATA(Py_slot_subslots, my_slots),
      PySlot_DATA(Py_tp_module, module),
      PySlot_END
   };
   return PyType_FromSlots(all_slots);
}

Public class function GetModuleByToken(type_: PPyTypeObject; const mod_token: Pointer): IPyObject;

Find the first superclass whose module has the given module token, and return that module.

If no module is found, raises a TypeError and returns nil.

This function is intended to be used together with TPyModule.GetState() to get module state from slot methods (such as tp_init or nb_add) and other places where a method's defining class cannot be passed using the PyCMethod calling convention.

Added in version 3.15.

Public class function GetModuleState_DuringGC(type_: PPyTypeObject): Pointer;

The following function should only be used in a tp_traverse handler; calling them in other contexts may have unintended consequences.

This function act like their counterpart without the _DuringGC suffix, but it's guaranteed to not have side effects, it doesn't set an exception on failure, and it returns/sets borrowed references as detailed in the individual documentation.

Note that this function may fail, but as it doesn't set an exception, no error information is available. In some cases, failure is not distinguishable from a successful nil result.
