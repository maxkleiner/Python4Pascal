type TPyInterpreterView = class(TInterfacedObject, IPyInterpreterView)

Description

A view of an interpreter.

In some cases, it may be necessary to access an interpreter that may have been deleted. This can be done using interpreter views.

This is a thread-safe way to access an interpreter that may have be finalizing or already destroyed.

<see href="https://docs.python.org/3.15/c-api/interp-lifecycle.html#cautions-regarding-interpreter-finalization">See the Python article about Cautions regarding interpreter finalization.)

Added in version 3.15.

Protected procedure Close;

Close an interpreter view.

If an interpreter view is never closed, the view's memory will never be freed, but there are no other consequences. (In contrast, forgetting to close a guard will infinitely hang the main thread during finalization.)

This function cannot fail, and the caller doesn't need to hold an attached thread state.

Added in version 3.15.

Public class function FromCurrent(): IPyInterpreterView;

Create a view to the current interpreter.

This function is generally meant to be used alongside TPyInterpreterGuard.FromView() or TPyThreadState.EnsureFromView().

On success, this function returns a view to the current interpreter; on failure, it returns NULL with an exception set.

The caller must hold an attached thread state.

Added in version 3.15.

Public class function FromMain(): IPyInterpreterView;

Create a view for the main interpreter (the first and default interpreter in a Python process; see TPyInterpreterState.Main()).

On success, this function returns a view to the main interpreter; on failure, it returns NULL without an exception set. Failure indicates that the process is out of memory.

Use this function when an interpreter pointer or view cannot be supplied by the caller, such as when a native threading library does not provide a void *arg parameter that could carry a PyInterpreterGuard or PyInterpreterView. In code that supports subinterpreters, prefer TPyInterpreterView.FromCurrent() so the guard tracks the calling interpreter rather than the main one.

The caller does not need to hold an attached thread state.

Added in version 3.15.
