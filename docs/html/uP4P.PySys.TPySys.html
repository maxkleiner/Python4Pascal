Public class function GetAttr(const name_: IPyObject): IPyObject;

Get the attribute name of the sys module. Return a strong reference. Raise RuntimeError and return nil if it does not exist or if the sys module cannot be found.

If the non-existing object should not be treated as a failure, you can use TPySys.GetOptionalAttr() instead.

Added in version 3.15.

Public class function GetAttrString(const name_: string): IPyObject;

This is the same as TPySys.GetAttr(), but name is specified as a string, rather than a IPyObject.

If the non-existing object should not be treated as a failure, you can use TPySys.GetOptionalAttrString() instead.

Added in version 3.15.

Public class function GetOptionalAttr(const name_: IPyObject; var result_: IPyObject): integer;

Variant of TPySys.GetAttr() which doesn't raise exception if the object does not exist. 

- Set result_ to a new strong reference to the object and return
  1 if the object exists.
- Set result_ to nil and return 0 without setting an
  exception if the object does not exist.
- Set an exception, set result_ to nil, and return -1, if an
  error occurred.

Added in version 3.15.

This is the same as TPySys.GetOptionalAttr(), but name is specified as a string, rather than a IPyObject.

Public class function GetObject(const name_: string): IPyObject;

Return the object name_ from the sys module or nil if it does not exist, without setting an exception.

Public class function SetObject(const name_: string; const v: IPyObject): boolean;

Set name_ in the sys module to v unless v is nil, in which case name_ is deleted from the sys module. Returns True on success, False on error.

Public class function GetXOptions: IPyObject;

Return the current dictionary of -X options, similarly to sys._xoptions. On error, nil is returned and an exception is set.

Public class function AuditTuple(const event: string; const args: IPyObject): boolean;

Similar to TPySys.Audit(), but pass arguments as a Python object. args must be a tuple. To pass no arguments, args can be nil.

Public class function AddAuditHook(hook: Py_AuditHookFunction; userData: Pointer): boolean;

Append the callable hook to the list of active auditing hooks. Return True on success and False on failure. If the runtime has been initialized, also set an error on failure. Hooks added through this API are called for all interpreters created by the runtime.

The userData pointer is passed into the hook function. Since hook functions may be called from different runtimes, this pointer should not refer directly to Python state.

This function is safe to call before TPy.Initialize(). When called after runtime initialization, existing audit hooks are notified and may silently abort the operation by raising an error subclassed from Exception (other errors will not be silenced).

The hook function is always called with an attached thread state by the Python interpreter that raised the event.

See PEP 578 for a detailed description of auditing. Functions in the runtime and standard library that raise events are listed in the audit events table. Details are in each function's documentation.

If the interpreter is initialized, this function raises an auditing event sys.addaudithook with no arguments. If any existing hooks raise an exception derived from Exception, the new hook will not be added and the exception is cleared. As a result, callers cannot assume that their hook has been added unless they control all existing hooks.

Public class procedure WriteStdout(const format_: string; const args: array of const); overload;

Write the output string described by format to sys.stdout. No exceptions are raised, even if truncation occurs.

format should limit the total size of the formatted output string to 1000 bytes or less – after 1000 bytes, the output string is truncated. In particular, this means that no unrestricted "%s" formats should occur; these should be limited using "%.<N>s" where <N> is a decimal number calculated so that <N> plus the maximum size of other formatted text does not exceed 1000 bytes. Also watch out for "%f", which can print hundreds of digits for very large numbers.

If a problem occurs, or sys.stdout is unset, the formatted message is written to the real (C level) stdout.
